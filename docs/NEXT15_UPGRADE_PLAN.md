# Next.js 15 upgrade plan (web/ front door)

Written 2026-11-23. Owner: Josh. Spike branch: `spike/next-15` (local, commit `d39e819`).

## Why

- Next 14.2.35 is the last 14.x release. `npm audit` lists 26 advisories against it: 3 critical, 9 high, 11 moderate, 3 low.
- Every one is fixed in **15.5.29** (npm tag `backport`). Nothing requires Next 16.
- #189 closed the image-optimizer RCEs by setting `images.unoptimized`.
- These advisories still apply:
  - Server Components / Server Actions DoS
  - rewrite SSRF and request smuggling
  - RSC cache poisoning
  - CSP-nonce XSS

  The fallback rewrite and the nonce CSP make the last two relevant to this site.

## The key finding: React 19 is not a prerequisite

The earlier estimate assumed the upgrade had to move the whole repo to React 19, SPA included. The spike shows it does not.

- The App Router never uses the installed `react`. Next bundles its own build of React:
  - Next 14.2 bundles `18.3.0-canary`. This is what prod runs today.
  - Next 15.5 bundles `19.2.0-canary`.
- `next@15.5.29` lists `react ^18.2.0 || ^19` as its peer dependency.
- The Vite SPA (`/admin`, plus client-side navigation) keeps the installed React 18.3.1. It is untouched.
- Effect: the shared components in `client/src/pages/content/*`, `components/ui/*`, wouter, React Query, Radix, recharts and framer-motion run on React 19 on Next pages and on React 18 in the SPA. The spike rendered them on React 19 with no hydration errors.

## What the spike changed (all of it)

| File | Change |
|---|---|
| `package.json`, lockfile | `next` ^14.2.35 → 15.5.29 (React stays 18.3.1) |
| `web/lib/generic-page.tsx` | `params: Promise<P>`, awaited in `generateMetadata` and `Page` (covers all ~30 generic routes) |
| `web/app/study/[slug]/page.tsx` | `params` awaited (2 places) |
| `web/app/studies/page.tsx` | `searchParams` awaited |
| `web/app/layout.tsx` | `RootLayout` made `async`, `await headers()` |
| `web/next.config.mjs` | `experimental.outputFileTracingRoot` → top-level `outputFileTracingRoot` |
| `web/next-env.d.ts` | regenerated by Next |

Breaking changes in Next 15 that need no work here:

- **`fetch` / GET route handler caching defaults:** every fetch already sets `cache: "no-store"`, and every route is `force-dynamic`.
- **`unstable_cache` and `revalidateTag`:** unchanged in 15.
- **Middleware `req.geo` / `req.ip` (removed in 15):** not used.
- **`next/link` prefetch and RSC navigation headers:** there is no `next/link`. `WouterBridge` does full page loads, so the Express proxy (`server/middleware/web-frontdoor.ts`) does not need to forward `RSC` headers.
- **`next/image`:** not used, and `/_next/image` still returns 404.

## Spike results (2026-11-23)

The spike ran locally against prod Express. Every request was a read-only GET.

- `next build web` passed. The bundle is the same size as before (103 kB of shared JS).
- `/`, `/studies`, `/learn`, `/research-analytics` and a study page all returned 200. A missing study returned 404. The "Last updated" bylines render the same as on prod.
- **Browser checks:** I loaded 9 pages in Chromium and saw **no hydration errors or new console errors**.
  - The SVG `height="auto"` and `orient` errors on `/learn` already happen on prod.
  - The 403 came from `/api/geo` refusing a localhost origin, so it only happens locally.
- **CSP:** the per-request nonce is in the header and on every executable inline script (25 of 25). The two inline scripts without a nonce are JSON-LD blocks, which browsers don't execute; prod has the same two.
- `/_next/image` returns 404.

## Rollout

1. **PR from `spike/next-15`.**
   - CI must pass: typecheck, vitest, `build:web`, E2E.
   - E2E is `continue-on-error`, so compare its failure list against the base branch (4 known fixture failures and 1 flaky sitemap test).
   - Also run `npx tsc -p web` and `npm run check`.
2. **Before merge, check the things the spike could not cover locally:**
   - `POST /web_revalidate` with `PAGE_DATA_KEY`: an admin edit should show on the next request.
   - The middleware 301s and 410s (`/index.html`, a legacy study URL, study 3566).
   - The contact form submits (CSRF priming plus POST through the fallback rewrite).
   - The cookie-consent banner, and that GA4 loads under the nonce.
3. **Merge in a quiet window.** Railway deploys both services from `hydrogen-studies`. Only the web service's behaviour changes; Express code is untouched.
4. **Watch for 30 minutes after deploy:**
   - Sentry: new web issues, especially hydration or `Minified React error`.
   - Railway: web 5xx rate, memory, and p99 against the current baseline (homepage p99 3.5 s).
   - The uptime monitors on `/web_health` and `/studies`.
5. **Verify live:** rerun the same checks from the session that verified #195 (bylines on `/`, `/studies`, `/research-analytics`), plus `/_next/image` → 404 and the CSP nonce.

### Rollback

- **Instant:** set `SSR_FAMILIES` to empty on the Express service. Express then stops proxying to Next and serves the SPA for every public route. This needs no build.
  - To restore it, set it back to the current value: `study,blog,hubs,policy,pages,studies,home,learn,analytics,profiles,evidence,data,products,evidence_profile`.
  - Express also falls back to the SPA by itself on any upstream 5xx.
- **Full:** revert the PR and Railway redeploys 14.2.35.

## Risks and open items

- **React 19 inside shared components.** No problems so far.
  - Spot-check the interactive parts on Next pages: Radix dialogs and tabs, recharts on `/research-analytics`, the `/studies` filters, and the contact form (react-hook-form).
  - `react-helmet` is pulled into the web bundle (via `components/seo/*`). It still works on React 19: legacy class lifecycles. On Next pages it renders nothing useful anyway.
- **15.x backport window.** 15.5.29 is on Next's `backport` line. A later critical advisory may only be fixed in 16.x. Plan Next 16 next quarter (Node ≥ 20.9; prod is on 22; `middleware` → `proxy` rename; Turbopack builds).
- **Optional later phase: move the SPA to React 19** so both sides run one React version. That needs:
  - `@types/react` 19
  - replacing `react-helmet` with `react-helmet-async` or React 19's built-in metadata
  - `react-day-picker` 8 → 9
  - `framer-motion` 11 → 12
  - TipTap 2 → 3, which is also the open moderate advisory

  It is not needed for the security fix.

About half a day, including review and the deploy watch. The code change is already done on the spike branch. What remains is the PR, CI, the checks in step 2, and the deploy.
